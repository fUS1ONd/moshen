# AGENTS.md — ядро (moshen)

Форк ядра mihomo. Это **ядро**, оно подключается к Android-клиенту как Go-модуль.
Клиент: `fUS1ONd/Prizrak-Box-android`.

## Родословная

```
MetaCubeX/mihomo  →  snakem982/mihomo  →  legiz-ru/moshen  →  fUS1ONd/moshen (мы)
```

Наш прямой апстрим — **`legiz-ru/moshen`**. Он добавляет smart-группы, LightGBM,
singbox-convert; всё это не наше, править его без крайней нужды не надо.

## Ветки

| Ветка | Что это | Правила |
|---|---|---|
| `main` | наша рабочая ветка, default | сюда мержим фичи, отсюда тегаем релизы |
| `upstream-base` | точный слепок релиза апстрима | **никогда не коммитить**, только переставлять на новый релиз апстрима |

Фичи делаются в ветках `feat/*` от `main`, вливаются в `main`.

Собственные изменения держим **маленькой серией коммитов поверх апстрима** — так
обновление апстрима остаётся дешёвым. Обновляемся **ребейзом**, не мержем.

## Как обновиться до нового релиза апстрима

Легиз **не ведёт нормальные ветки** — у него ветка на версию с именами вроде
`claude/v1-19-29-smart-moshen-commits-m3ik6v`. Ориентироваться надо на
**страницу Releases**, а не на ветки.

```bash
git fetch upstream --tags
# посмотреть последний релиз: https://github.com/legiz-ru/moshen/releases
git checkout upstream-base && git reset --hard <новый-тег-апстрима>
git push --force-with-lease origin upstream-base
git checkout main && git rebase upstream-base
# прогнать CI, убедиться что зелено, затем
git push --force-with-lease origin main
```

Ремоуты в клоне: `origin` (наш), `upstream` (legiz-ru/moshen),
`root` (snakem982/mihomo), `meta` (MetaCubeX/mihomo).

## Как выпустить релиз

Одной командой — пуш тега:

```bash
git tag v1.19.29-fs.1 && git push origin v1.19.29-fs.1
```

Дальше CI (`build.yml`) собирает бинарники под все платформы и публикует
GitHub Release. Ничего больше нажимать не нужно.

### Откуда берётся версия

Константы версии в репозитории нет — её вычисляет CI и вшивает в бинарник через
`ldflags` (`constant.Version`):

- сборка по тегу — версия равна самому тегу (`v1.19.29-fs.1`);
- ручной запуск с заполненным полем `version` — равна введённому значению;
- всё остальное — `<ветка>-<короткий хеш>`.

`VERSION` из `Makefile` (там `git describe --tags`) работает только при локальной
сборке. CI свою версию считает сам, поэтому мелкий клон без тегов ему не мешает.

В отличие от клиента (`fUS1ONd/Prizrak-Box-android`, где `versionName` — константа
в `build.gradle.kts`), бампить версию руками не нужно: достаточно правильно назвать тег.

### Схема версий

`v<версия-апстрима>-fs.<N>` — например `v1.19.29-fs.1`, `v1.19.29-fs.2`.
Из имени сразу видно, на какой базе апстрима стоим.

### ⚠️ Имена тегов нельзя переиспользовать

Контрольные суммы опубликованных версий модуля навсегда записаны в sumdb Go.
Тег с уже использованным именем, но другим содержимым, сломает сборку всем.
**Никогда** не создавай теги `v1.19.30-fast-switch` и `v1.19.31-fast-switch` —
эти имена уже сожжены. Каждый релиз получает новое имя.

## CI

| Workflow | Когда | Что делает |
|---|---|---|
| `ci.yml` | пуш/PR в `main` | build + vet + test, одна ОС, ~2-3 мин — основная проверка |
| `test.yml` | вручную | полная матрица апстрима: 6 ОС × 7 версий Go = 42 джобы |
| `build.yml` | пуш тега `v*` | сборка бинарников под все платформы + публикация релиза |

Docker-образ по умолчанию выключен (клиенту он не нужен). Включается переменной
репозитория `ENABLE_DOCKER=true`.

## Локальная проверка перед коммитом

```bash
go build -tags with_gvisor ./...
go vet -tags with_gvisor ./...
go test ./... -count=1 -tags with_gvisor
```

## Проверка поведения на живой сети

Изменения в переподключении, health-check и работе групп юнит-тестами не
ловятся — им нужен стенд со смены реальной сети. Он описан в
[`docs/testbed-linux.md`](docs/testbed-linux.md): гашение физического Wi-Fi под
TUN с `auto-route`, замер времени восстановления и флаппинга групп, серии
прогонов и сравнение с эталонным бинарником.

**Прочитай его до того, как запускать ядро в TUN-режиме:** `auto-route`
забирает весь трафик машины, включая SSH, и без описанных там мер машина
отрезает сама себя.

## Связь с клиентом

Клиент подключает ядро через `replace` в двух файлах
(`core/src/main/golang/go.mod` и `core/src/foss/golang/go.mod`):

```
replace github.com/metacubex/mihomo => github.com/fUS1ONd/moshen <тег>
```

Путь модуля в нашем `go.mod` остаётся `github.com/metacubex/mihomo` —
**переименовывать его нельзя**, иначе поедет вся цепочка `replace` и импорты.

Порядок выкатки изменения ядра в клиент:
1. тег в ядре → CI публикует релиз;
2. в клиенте запустить workflow `Update Moshen Core and Go Modules` — он сам
   поправит `replace` в обоих `go.mod`, прогонит `go mod tidy` и откроет PR.

## Agent skills

Репозиторий настроен под инженерные скиллы (`/setup-matt-pocock-skills`).

### Issue tracker

Задачи и спеки живут локальными markdown-файлами в `.scratch/<feature>/` — ни GitHub Issues,
ни внешний трекер не используются. См. `docs/agents/issue-tracker.md`.

### Triage labels

Пять канонических ролей без переименований (`needs-triage`, `needs-info`, `ready-for-agent`,
`ready-for-human`, `wontfix`). См. `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `CONTEXT.md` и `docs/adr/` в корне репозитория. См. `docs/agents/domain.md`.
